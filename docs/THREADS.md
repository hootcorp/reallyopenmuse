# Conversation threads and the agent computer

OpenMuse uses a small dependency-free AG-UI client (`packages/agui`) and its own React Native screens. Chat messages, tool cards and task-linked documents are rendered from the AG-UI event stream served by the local runtime at `/api/agui`.

## Threads

Threads are stored by the OpenMuse API in the same database as everything else (embedded PGlite or PostgreSQL). No external service and no project key are needed.

- `GET /api/main-thread` returns the owner-bound main conversation (created on first use).
- `GET /api/threads?includeArchived&limit&cursor` lists conversations with cursor pagination.
- `GET /api/threads/:id/messages` and `PUT /api/threads/:id/messages` read and save a conversation's messages.
- `PATCH /api/threads/:id` renames or archives/restores a thread.
- `/api/conversation` remains an alias of the main thread.

The client saves the conversation after each completed run. A run that is aborted mid-way is not persisted, and a run in progress is not replayed after reloading the app. Automatic thread naming is disabled; conversations can be renamed in the menu. Side chats create a fresh thread ID and are persisted on their first run. The deployment is a single-user workspace; its access key must not be shared as a multi-user login.

The composer stays editable during replies. Follow-ups enter a visible, removable queue and run in order after the current reply and its persistence finish. Stopping or failing a reply pauses the queue. The queue lives in the open app, not a durable server inbox. Delegated tasks remain separate server work.

Rich tool messages retain task IDs. The renderer fetches current task status, browser previews, PDF links and structured artifacts from the authenticated task endpoint. Expiring file/preview URLs are generated by the server rather than stored in thread messages.

## Agent computer

The Computer control below the avatar opens a persistent workspace with browser sessions and files. Browser cards show actual worker screenshots; **Open browser** opens the existing interactive console for takeover. PDFs open in the native/web readers. Tasks can read public pages, monitor changes and collect PDFs using the same worker.

Opening a session renews its short-lived console access. **Refresh connection** renews access without navigating; **Reopen** keeps the saved profile and uses the address in the input. The console reports live/disconnected state, preserves unsent text after an error, and pauses preview polling when hidden. Closing a session retains its profile and downloads.

Run the browser worker using the `BROWSER_WORKER_URL` and `WORKER_TOKEN` setup in the [README](../README.md). Browser profiles persist on disk. The optional [Linux computer](COMPUTER.md) adds real command execution, saved output, editable files, and PDF transfer. The built-in conversation and task-worker tools use this same computer; a remote AG-UI backend (`AGENT_BACKEND=agui`) must supply its own equivalent tools.

## Validation scope

`tests/threads.test.ts` and `tests/agui-runtime.test.ts` cover owner scoping, pagination, rename, archive, message round-trips and the SSE run endpoint against the local runtime. `apps/mobile/test/agui.test.ts` covers the client event reducer, SSE parser and run lifecycle. None of this has been exercised on a physical device or with a live model.
